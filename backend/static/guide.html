Datalogger Provisioning Guide

How to put a Raspberry Pi datalogger on a plant, and how to change it later, using the onboarding dashboard. Nothing is typed on the Pi itself. The dashboard explains itself as you go: every step has a How this step works box, every unusual word has a ? next to it, and the Tags step has a Which type? helper. This guide is the longer version.

Who does what

Field / electrical engineer

Mounts the Pi, gives it power and an Ethernet cable to the site router (client internet or the SIM‑based 4G router), reads the 6‑digit device code off the Pi's OLED display. Wires RS485 meters and sets their slave IDs.

PLC programmer

Owns the Modbus addresses. Hands over a CSV of tag, address, type for every value the PLC exposes, and tells you when an address changes.

Ops / IoT engineer

Runs the dashboard: pairs the Pi, enters the plant, imports the tag list, pushes the config. Pushes a new version whenever something changes.

The Pi runs one base image that is identical on every site (the datalogger service under pm2). Everything specific to a plant lives in a config.json that the server builds and sends to the device as an AWS IoT job; the device saves it, reports success and restarts the service. The Pi fetches its own certificate; no one copies certificates around.

On boot the Pi shows its state on the small OLED: Health check (waiting for CPU temperature / RAM to settle), Waiting for internet, then Device code 482 913. Two buttons sit next to it: hold the restart button to restart the service; press the scan button to list the USB serial ports on the display (useful when adding an RS485 converter).

Before you start

The same four items are shown as a checklist at the top of the Device step.

  • The Pi is powered and on the site router by Ethernet. Within about two minutes it registers itself and shows up under Waiting to be assigned. Wi‑Fi is not used.
  • You have the PLC's IP address on the plant LAN, and the port and unit ID if the integrator changed them (defaults 502 and 1).
  • You have the tag list from the PLC programmer (see CSV format). Without the Modbus addresses there is nothing to read; the IO list and wiring drawings do not contain them.
  • For RS485 meters or probes on a USB converter: their slave IDs, baud rate and parity, from whoever wired them.
  • Tailscale is not needed for onboarding. It only matters for remote support later.

Onboard a new plant

Five steps, top of the dashboard. You can go back at any time; nothing reaches the Pi until you press Push config to device on the last step.

1

Device

Click the Pi in the waiting list, or type its device code. The code is shown on the Pi's OLED display after boot and is the only thing a field engineer needs to read out to you. An offline device can still be set up: the config waits as a job and applies when the Pi reconnects.

If the Pi is not listed, open My device isn't listed and work through the checklist with whoever is on site. Power first, then the Ethernet link light, then whether the router has internet.

2

Plant

Name the plant. The Plant ID is derived from the name, becomes the data topic (<plant-id>/pub, which the IoT rule forwards to SQS) and cannot change after the first push, so check it before moving on. One datalogger serves one PLC; a plant with two PLCs gets two loggers and two PLC IDs.

Send data every is how often the Pi sends a payload. 60 seconds is the standard; go shorter only when the process needs it. Extra logging on the Pi is for the support team while they investigate a problem; switch it off again afterwards. The data topic, the Pi's cloud identity and the certificate are under Technical details; they are set up automatically and you never need to touch them.

3

Connections

Enter the PLC's IP. Test connection asks the Pi to reach the PLC from the plant side; if that fails, the Pi and PLC are not on the same network or the PLC's Modbus server is off.

Number format (under Advanced) is the one setting that is sometimes wrong and hard to guess. PLCs split a decimal across two registers in one of four ways, called ABCD, CDAB, DCBA and BADC. Leave it on ABCD. If decimals later come out as nonsense, do not guess: the Tags step has Find the number format, which works it out from a single known reading (see step 4).

On/off values differ by PLC brand: some keep each one as a coil, some as an input, some pack sixteen into one register (Delta vs Fuji). That is chosen per tag in step 4, not here.

Add each meter or probe wired to the Pi with a name you will recognise later, which converter it is on (USB 1 or USB 2), its speed, parity and address. These three come from the meter's own menu or from whoever wired it; typical values are 9600, none and 1. Two meters on one converter cannot have the same address. With more than one meter on a converter the Pi pauses about six seconds between them; the dashboard shows the resulting round time and warns if it is longer than the sending interval.

4

Tags

One row per value you want from the plant. The fastest way is Import CSV with the PLC programmer's list; rows with problems are shown and skipped, the good ones are imported. Or add rows by hand.

  • Tag: the DigitalPaani standard name (for example PH_AXTdd1_1:ADA_ADA, FMF_EQTdd1ssAXTdd1_1:ADA_ADA). It is the key in every payload, so agree it once.
  • Type: what the PLC stores at that address, in plain words with the PLC programmer's word in brackets. Ask the programmer which it is and pick the matching row:

  • A type that uses two or four registers occupies the address and the next ones; the next tag must start after them. The dashboard flags any overlap.
  • Bit: only for bit in a register. Up to sixteen on/off tags may share one register, each with its own bit. The picture Bits inside registers under the table shows every such register as sixteen cells; a red cell means two tags claim the same bit.
  • Scale: multiply the raw value. A PLC that stores pH 7.2 as the integer 72 needs scale 0.1; a 4–20 mA value stored as 0–27648 needs its own factor.
  • Role: Use as it is for most tags. Already a running total when the PLC itself keeps a running total (kWh, m³). A rate · make a running total when the Pi should add a flow rate up into a running total: it sends <tag>_total, keeps it across restarts and never lets it decrease, even when a sensor misfires.
  • Zero below: flow sensors read a little noise when pumps and valves are off. Values below this threshold are sent as 0.

Red rows mean the config cannot be pushed; the message under the table says what to fix and names the row. How the Pi will read it shows the reads the Pi will make each cycle. You do not edit it; it is worked out from the addresses.

Find the number format: take any decimal tag whose live reading you know (pH 7.2, say). Ask the PLC programmer for its two raw register values, or read them with any Modbus tool. Enter the expected reading and the two registers; the dashboard decodes them all four ways, marks the one that reproduces 7.2 and offers Use. That sets the number format for the PLC. Without an expected reading it still shows the four results and colours the nonsense ones red.

5

Review and push

Check the four cards, then Push config to device. The timeline shows the job reaching the Pi, the Pi applying it, and the first payload arriving, with live values in tiles. If the device is offline the timeline waits at Waiting for the Pi to come online; leave the page, the job stays queued.

If the push fails with a message from the Pi (for example a serial port that does not exist), fix the step it names and press Try again.

Change a running plant

On the Device step, pick the plant under Change a plant that is already running. Its current config loads, the assigned Pi is selected, and you land on the Tags step. Make the change and push; the Pi receives the next version number and switches over without a reboot. Every version is kept on the server.

tag
The DigitalPaani standard name: letters, digits, _ and :, starting with a letter. This is the key the data carries forever, so agree it once.
address
The Modbus holding‑register address (or coil / discrete‑input address for booleans), as the PLC programmer defined it.
type
REAL (float32), DOUBLE (float64), INT (int16), UINT/WORD (uint16), DINT (int32), UDINT (uint32), BOOL (coil), DI (discrete input). A BOOL with a bit number is a packed bit of a holding register.
bit
0–15, only for packed booleans.
scale
Optional, default 1 (the Scaling_Factor of the device config).
source
PLC, or the exact name you gave an RS485 device on the Connections step.
role
flow to have the Pi integrate a rate into <tag>_total; counter for a register that already totals; empty otherwise.
zero_below
Optional flow‑noise threshold.

The compiled config.json carries the same information twice: in the structured tags/polls sections, and as the flat POLLING_INTERVAL, ANALOG_SENSORS (start, end, data_type, word_order, Scaling_Factor) and BOOLEAN_SENSORS (address, fc, bit_index) keys the existing main.py loads. Either runtime can use it.

Run the demo

For a presentation on a laptop, with no plant and no AWS:

python demo.py

It resets the local database, starts the backend and three simulated Pis, seeds one plant that is already running, and opens the dashboard. You then have a Pi waiting with its device code shown, a running plant to edit, and a third Pi that drops offline after about 90 seconds. Ctrl+C stops everything.

Glossary

Device code
Six digits issued when the Pi first registers, shown on its OLED and cached on the device. Proves the person on site has the physical device; a cloned SD card cannot push data as another plant.
Packed bits
Sixteen on/off states stored in one holding register; each tag names the register and its bit index.
Job
One config version sent to one Pi. Queued → sent → applied, or failed with a message from the Pi.
Poll block
One Modbus read request: a start address and a count. The dashboard merges nearby tags into blocks and splits at the Modbus limit of 125 registers.
Number format (word order)
How a PLC splits a 32‑bit value across two 16‑bit registers: ABCD, CDAB, DCBA or BADC. ABCD is the common case; Find the number format on the Tags step works it out from one known reading.
Meter, probe
Any RS485 device wired to the Pi's USB converter and read directly, rather than through the PLC: energy meters, flow meters, MLSS or DO probes.
Totaliser
A value that only increases, such as a flow total or energy meter reading.
Source
Where a tag is read from: the PLC over Modbus TCP, or an RS485 device over a USB converter.
Topic
<plant-id>/pub, the MQTT address the Pi publishes to; one IoT rule on +/pub forwards every site to SQS. <plant-id>/control carries remote‑control commands back to the Pi, <plant-id>/health its CPU, RAM and buffer status.
Payload
One flat JSON object per cycle: plantId, plcId, TIMESTAMP, then one key per tag. While the internet is down the Pi stores them locally and replays one old payload per cycle once it is back.
